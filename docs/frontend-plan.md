# Vue-фронт VK Mini App: рабочий функционал + расширяемый каркас

## Контекст

Бэкенд готов и проверен: JSON-API `/api/v1` (auth по подписи VK → Bearer JWT,
карты, состояния разборов с поллингом, пейволл с внешней оплатой). Первая
заявка в каталог VK отклонена 2026-08-20, приложение переделано в бесплатное;
**модерация пройдена 2026-08-27** — приложение одобрено на всех площадках, но
только по прямой ссылке, вне каталога (см.
[astro-context.md](astro-context.md), «Где мы сейчас»). Mini App сейчас
показывает Jinja-стенд, и замена его на Vue повторного ревью не требует.
Утверждены макеты дизайна (тёмная «мистическая»
тема: почти чёрный фон, золото, засечковые заголовки, капс-лейблы с
разрядкой). Задача: Vue-фронт поверх `/api/v1` с этим дизайном, покрывающий
**только работающий функционал** (онбординг → карта → бесплатный разбор →
пейволл → полный разбор → таблицы карты), но с каркасом, в который
совместимость, Матрица Судьбы, восточный гороскоп и «прогноз на месяц»
добавляются без переписывания. Будущие разделы — плитки «скоро», как в
макете. Расширение админки — отложено (отдельный план). Тот же фронт позже
поедет в веб (вход cookie/анонимная сессия) и Telegram Web App (вход по
HMAC от initData) — платформо-зависим только слой получения токена.

## Ключевые решения

- **Без Pinia**: composables-синглтоны (`useSession`, `useCharts`,
  `useReports`) — состояния три, миграция на Pinia при росте механическая.
- **vue-router 4 с hash-историей**: VK кладёт `vk_*` и `sign` в query
  iframe-адреса; hash-роутинг не трогает `location.search`, и параметры
  запуска доживают до auth. Тот же режим работает в вебе и TG.
- **Реестр типов разборов + конфиг плиток**: экран разбора — один
  generic-компонент, управляемый `ReportOut` (тип/статус/секции/цена).
  Неизвестный фронту тип из API рисуется generic-плиткой — бэкенд может
  добавить тип без синхронного релиза фронта.
- **Несколько карт: переключатель в шапке главной.** Бесплатный текст даётся
  один на карту, а личного лимита с 01.09.2026 нет (`FREE_NATAL_LIMIT=0`),
  значит «второй бесплатный разбор» = вторая карта, и
  вход за ней обязан быть в интерфейсе. Выбранная карта живёт в
  `useCharts` (`current`, `select`) и **только в памяти**: сессия в VK и
  так на один запуск, а сохранённый token удалённой карты воскрес бы из
  хранилища. Не выбирали — показываем самую свежую, как раньше. Новая
  карта становится текущей внутри `remember()`, поэтому онбординг об этом
  ничего не знает. Управление держим на словах, а не на иконках: круг с
  буквой в шапке (первая версия) не читался как список — переключателем
  стало имя со стрелкой, а «завести карту» переехало в карточку с
  заголовком и подписью, сразу за плитками разборов. Оттуда же следует
  «Отмена» на первом шаге онбординга — но только у того, у кого карта уже
  есть: первого пользователя guard всё равно вернёт назад.
- **Адаптеры платформ**: `platform/vk.js` (и стабы web/telegram) —
  единственная платформо-зависимая точка. Контракт шире, чем одна
  авторизация, и фиксируется сразу целиком (дописать метод в стаб дёшево,
  разыскать по коду прямые вызовы `bridge.send` — нет):
  `init()`, `obtainToken(http)`, `openExternal(url)`, `onBack(handler)`,
  `setHeaderColor()`, `close()`, `supportsGroup()`, `joinGroup(groupId)`,
  `allowMessages(groupId)`. Прямых обращений к `vk-bridge` вне
  `platform/vk.js` быть не должно. См. «Три платформы» ниже.
- **Оплата только наружу**: `<a :href="pay_url" target="_blank"
  rel="noopener">`; `pay_url === null` при `locked` = «покупка временно
  недоступна», кнопки нет (правило из progress.md 2026-08-18).
- **Dev**: vite `server.proxy` `/api` → `localhost:8000` — same-origin, CORS
  в бэкенд не добавляем. Туннель — localhost.run (vk-tunnel сломан).
- **Tailwind CSS 4** (`@tailwindcss/vite`) вместо рукописного CSS: утилиты
  в шаблонах, свои цвета/шрифты/радиусы — токенами в `@theme` (CSS-first
  конфиг, без tailwind.config.js). Tailwind работает на этапе сборки —
  внешних CDN по-прежнему нет. Рукописного CSS остаётся минимум:
  `@font-face` и пара сложных декоративных элементов (пунктирная карточка,
  золотые рамки можно утилитами).
- **Шрифты self-hosted** (woff2 в `assets/fonts`, Cormorant/PT Serif +
  системная стопка) — внешних CDN нет.
- Токен JWT (24 ч) держим в памяти, в storage не пишем; на 401 —
  single-flight повторный `obtainToken()` и один повтор запроса.
- **Большие экраны — одна колонка, второго лэйаута нет** (решение
  2026-08-18, разбор ниже).
- **Блок сообщества и оценка разбора** (перенесены со снятого стенда
  01.09.2026). Три решения, которые иначе отменят по незнанию:
  - `group_id` фронт берёт из ответа `GET /api/v1/vk/group-state`, а не из
    переменной сборки `VITE_*`. Второй экземпляр числа однажды разъехался
    бы с тем, по которому бэкенд считает `joined` через `groups.isMember`.
  - Состояние сообщества вынесено в `useGroup` — четвёртый
    composable-синглтон. Блок стоит на двух экранах (конец разбора,
    профиль), а запрос состояния на бэкенде ходит по сети в VK: держи
    состояние в компоненте, и профиль спрашивал бы VK при каждом открытии.
  - `joined === null` («VK не ответил») трактуется как «не подписан», и
    кнопка подписки показывается: предложить лишний раз дешевле, чем
    спрятать её у того, кто на самом деле не подписан.
  - Оценка уходит одним запросом по кнопке, а не тапом по звезде: иначе
    звезда и последующий комментарий дали бы два события `feedback`, и один
    человек считался бы в аналитике дважды. Факт «уже оценил» живёт только
    в памяти компонента — бэкенд его не отдаёт, при перезагрузке экрана
    звёзды спрашиваются снова.

## Большие экраны (ноутбук, десктоп, планшет)

Десктопной вёрстки не делаем: контент всегда в одной колонке
`max-width: 26rem` (~420 px, естественная мера макета),
`margin-inline: auto`. Причина в том, кто вообще открывает нас на широком
экране:

- **VK desktop** (`vk.com` в браузере) — Mini App сидит в iframe внутри
  вёрстки VK, ширина контейнера ограничена самой VK (порядка 700–1000 px,
  точное значение зависит от их лэйаута и `VKWebAppResizeWindow` —
  замерить живьём на шаге 1). Даже на большом мониторе мы получаем окно
  приложения, а не ширину экрана. Среда различима по `vk_platform` из
  launch params (`desktop_web` против `mobile_*`), параметр и так проходит
  через `platform/vk.js`.
- **Telegram Web App на десктопе** — окно порядка 400 px, это мобильный
  лэйаут.
- **Настоящий десктоп-браузер** остаётся только у веба, а веб по стратегии
  не приложение, а платёжный и SEO-хаб на Jinja/`site` — широкий
  интерфейс нужен лендингу, не этим экранам.

Что из этого следует для вёрстки:

- Кегли и отступы на широком экране **не растягиваем**: пропорции макета
  посчитаны под 390 px, увеличенный шрифт выглядит как «версия для
  слабовидящих». Размеры пишем в `rem`/токенах — второй брейкпоинт, если
  понадобится, меняет токены, а не разметку.
- Фон за колонкой не пустой: `--color-bg` плюс слабое радиальное свечение
  и волосяные золотые линии по краям колонки. Десяток строк CSS,
  превращающих «текст в углу пустой страницы» в осознанный кадр.
- **BottomNav привязан к колонке, а не к вьюпорту**: `width: min(100%,
  26rem)` + центрирование. Иначе на широком экране панель растягивается
  во всю ширину и разваливает композицию.
- Hover-состояния (рамка плитки светлеет) и клавиатура в онбординге
  (Enter = «Дальше», видимый фокус) — на мобильном их нет, на десктопе их
  отсутствие читается как неживой интерфейс. Стоит несколько утилит.
- **Исключение, которое обсуждали и отклонили: ChartView.** Таблицы
  планет, домов и аспектов в 420 px тесные, но колонка не расширяется и
  там — сетка аспектов уезжает в горизонтальный скролл. Разъезжающаяся на
  одном роуте колонка — первый шаг к двум лэйаутам; вернуться к этому,
  если аналитика покажет заметный `desktop_web` на карте.

## Экраны первой итерации

1. **Онбординг** — мастер 4 шага со StepDots (I·II·III): дата → время
   (+«не помню» → `birth_time: null`) → город (`GET /api/v1/places?q=`,
   debounce 300 мс) → имя (необязательно) → `POST /api/v1/charts` (201 или
   дедуп) → `/home`.
2. **Главная** — приветствие (`person_name`, `birth_local`); бейджи
   Солнце/Луна/Асцендент из `calc.natal` (`planets[].sign_ru`,
   `angles.asc.sign_ru`); при `time_known=false` асцендент считан от
   полудня — вместо знака показываем «уточните время». «Сегодня» —
   заглушка «скоро». Плитки разборов из реестра + пунктирный анонс.
   Имя в шапке — переключатель карт (`ChartSwitcher`): тап разворачивает
   список карт с отметкой текущей. Вход за новой картой — не в этом
   списке, а карточкой `AddChartCard` сразу за плитками разборов.
3. **ReportView (generic)** по `ReportOut.status`:
   `available` → анонс `section_titles` + кнопка → POST → `running`;
   `running` → поллинг GET раз в 3 с (пауза при `document.hidden`,
   таймаут ~5 мин); `ready` → `sections[]` (у free_natal одна секция без
   title — сплошным текстом); `locked` → PaywallCard (цена, состав, ссылка
   наружу; после клика — поллинг + refetch на `visibilitychange`);
   `failed` → тексты по `error_code` (limit_exhausted, needs_purchase,
   budget_exceeded, not_supported, failed), `error` — fallback.
   Под готовым текстом — оценка (`ReportFeedback`) и блок сообщества
   (`GroupCard`): соглашаются на письма от того, чей текст только что
   понравился.
4. **ChartView** — таблицы планет (name_ru, sign_ru, deg_in_sign, house,
   retrograde), домов и аспектов из `GET /charts/{token}` → `calc.natal`.
   Своего запроса нет: расчёт лежит в кеше `useCharts`, тот же, что кормит
   бейджи главной. Три таблицы — один компонент `ChartTable` со строками
   «имя — значение — приписка»: колонки у них одинаковые, а тройная правка
   вёрстки разъезжается на второй итерации. Градусы с минутами
   (`11°08′`), минуты округляются точно как в `scripts/natal_cli.py`
   (усечение расходилось бы с нашим же сверщиком на минуту). При
   `time_known=false` таблицы домов нет вовсе, а у планет скрыт номер дома —
   от полудня они означают чужую карту. SVG-колесо — потом
   (astro_core/wheel.py пуст).
5. **BottomNav**: Главная / Карта / Пара / Профиль. Первая итерация вела две
   последние на `SoonView`; сейчас работают все четыре — «Пара» ведёт в список
   пар и подсвечивается на всех экранах раздела (их имена начинаются с `pair`).

## Механизм расширения (то, ради чего каркас)

`features/report/reportTypes.js` — единственное место со знанием о типах:
```js
export const REPORT_TYPES = {
  free_natal: { order: 1, icon: 'natal', tileTitle: 'Натальная карта' },
  full_natal: { order: 2, showOnTile: 'inside-free' },  // пейволл на экране натала
  matrix:     { order: 3, icon: 'matrix',  comingSoon: true },
  eastern:    { order: 4, icon: 'eastern', comingSoon: true },
}
```
`homeTiles.js` мерджит реестр с ответом `GET .../reports`. Новый тип =
строка в реестре (+ опц. `component: () => import(...)`, если generic-экрана
мало). Плитки вне разборов («Сегодня», «Пара») — записи `homeTiles.js` с
`route`/`comingSoon`.

Каркас проверен совместимостью: она стала своей feature-папкой и своими
роутами, а api-слой, поллинг, экран разбора, витрина оплаты и токены дизайна
переиспользованы как есть (раздел ниже).

## Раздел «Совместимость» (сделано)

Схема БД — в [db-schema.md](db-schema.md), решения по доступу, инвайту и
оплате — в [astro-context.md](astro-context.md), промпты — в
[astro-prompts-v2.md](astro-prompts-v2.md), раздел 8; здесь только фронт.

**Шесть экранов, четыре из них уже были.** Своих ровно два — список пар
(`PairsView`) и сборка (`PairCreateView`); плюс экран пары (`PairView`) и
анонимное приглашение (`InviteView`). Разбор, витрина оплаты и возврат с
неё — те же `ReportView`, `PayView`, `PaidView`, что у карты: форма
`ReportOut` у пары и карты одна, и второй копии экрана нет.

Решения, которые иначе отменят по незнанию:

- **`useReports` ключуется парой «вид владельца + токен»**, вид задаётся
  один раз (`useReports('pair')`), ручки выбираются по нему же. Поэтому пять
  экранов, знающих только карты, не тронуты вовсе, а `ReportView` узнаёт вид
  из `meta.scope` своего маршрута — внутри `computed`, а не один раз при
  создании: роутер переиспользует компонент между `report` и `pair-report`, и
  замыкание осталось бы ходить в прежние ручки.
- **`usePairs` — отдельный синглтон, а не ветка `useCharts`**: в тот смотрит
  guard роутера, решая «гнать ли в онбординг», и пары в этом решении не
  участвуют. Сверх образца у него есть `reloadDetail` (партнёр приходит без
  нашего участия) и нет «выбранной» пары.
- **Список пар перечитывается при каждом заходе** (`reload`, не
  `ensureLoaded`): пара, ждавшая партнёра, становится собранной сама, и кеш
  соврал бы ровно в тот момент, ради которого человек и зашёл.
- **Флагов у роутов два, а не один.** `meta.public` — «экран открыт без
  карты» (читает guard роутера), `meta.guest` — «экран работает без сессии»
  (читает гейт в `App.vue`). У приглашения оба, у онбординга только первый:
  карты у человека нет, но токен ему нужен, иначе «Готово» упрётся в 401.
  Один флаг на оба смысла показал бы форму онбординга тому, у кого сорвался
  вход, вместо кнопки «Повторить». Список пар и сборка не публичны вовсе:
  свою сторону пары взять неоткуда.
- **Экран возврата с оплаты узнаёт вид владельца из `order.report_type`,** а
  не из маршрута: адрес возврата сервер строит один на карту и пару
  (`/paid/<token>`), и в токене не написано, чей он. Маршрута `pair-paid`
  поэтому нет.
- **Мостик к платному — блок интерфейса, а не фраза промпта** (таблица
  `BRIDGE` в `ReportView`, показывается при `platform.name === 'web'`). Текст
  кешируется один на пару, площадка в ключ кеша не входит, и фраза из промпта
  поехала бы и в VK, где продавать нельзя, — ровно та ошибка, из-за которой
  мостик уже убирали из `free_natal_v3`. Числа в фразе сверены с кодом:
  6 контактов в тизере (`pair_free.TOP_ASPECTS`), 12 в платном
  (`synastry.TOP_LIMIT`).
- **Анонимная ветка ходит только в `/invites/*`** с флагом `anonymous: true`
  у запросов: партнёр нам никем не представлен, и его 401 не должен запускать
  перевыпуск сессии. Экран сам различает «ссылка мертва» и «ею уже вошли»,
  спрашивая приглашение, а на 404 — текст по той же ссылке (это единственный
  вход партнёра к разбору про него самого).
- **У приглашения предупреждение стоит до формы, а не после.** Данные
  партнёра сохранятся в аккаунте пригласившего (152-ФЗ), и мастер ввода
  открывается только по кнопке. Форма даты рождения на первом кадре от
  незнакомого сервиса — отказ, а не конверсия.
- **В ветке упавшей генерации у партнёра нет кнопки повтора.** Сервер по GET
  упавшую генерацию не перезапускает (иначе опрос раз в пять секунд платил бы
  за каждый круг), а приглашение после приёма закрыто: заказать текст заново
  может только владелец пары, так и написано в тексте экрана.
- **Тексты шага имени в мастере — пропы** (`nameTitle`, `nameHint`): у
  натальной карты имя в разбор не идёт, у стороны пары идёт, и обещать
  обратное нельзя.

## Макеты (`images/`) — анатомия экранов

Композиция: всё по центру, крупные вертикальные интервалы, экран не
скроллится — блок «эмблема + шаг» прижат к верхней трети, кнопка к низу.

### Что на макете есть, а в бэкенде — нет

Макет нарисован на вырост, вёрстка первой итерации ему намеренно не
равна. Расхождения фиксируем здесь, чтобы они не всплывали как «баг»:

- **«Сегодня»** — на макете живой текст про транзит Луны. Транзитов в
  расчётном ядре нет: карточка верстается в состоянии-заглушке (текст
  «скоро»), место в макете за ней сохраняется.
- **«Матрица Судьбы» и «Восточный гороскоп»** — рисуем плитками, но с
  `comingSoon: true`: клик ведёт на `SoonView`, а не в разбор. Подписи под
  ними на макете подставные — «Металлическая Лошадь» считается в
  `astro_core/eastern.py`, которого пока нет, поэтому подпись нейтральная.
  «Совместимость» была такой же плиткой-анонсом и с фазой 5 стала рабочей:
  запись в `EXTRA_TILES` ведёт в `/pairs`, а не в `SoonView`.
- **Два круга в шапке** — на макете переключатель карт и профиль. Кругов
  не рисуем ни одного: переключателем стало само имя («Ключевые решения»
  выше), а профиль отложен, вход в него есть в нижней навигации.
- **Иконки плиток** — четыре штриховых SVG (колесо, два кольца, ромб в
  квадрате, месяц). Рисуем вручную в `shared/ui/icons`, никаких
  иконочных пакетов: их вес и внешний вид с макетом не совпадут.

## Деплой

Сделано не так, как планировалось здесь изначально: dist отдаёт не Caddy, а
само приложение, и собирается он внутри Docker-образа. Volume в caddy,
`build-frontend.sh` с rsync и `handle_path` в Caddyfile не понадобились —
раздача одним `mount` дешевле, а сборка в образе исключает расхождение между
кодом и залитым руками dist.

1. `vite.config.js`: `base: '/app/'` (+ proxy `/api` и страниц оплаты для dev).
2. `backend/Dockerfile`: стадия `frontend` (node:22-alpine) делает `npm ci &&
   npm run build`, готовый dist копируется в рантайм-образ; node в него не
   уезжает. Выкатка поэтому **только с `--build`**.
3. `main.py`: `mount("/app", StaticFiles(directory=FRONTEND_DIR, html=True))`.
   Монтируется, только если каталог есть, — локально без `npm run build`
   приложение всё равно стартует.
4. `Caddyfile`: immutable-кеш на `/app/assets/*` (в имени файла хеш
   содержимого), no-cache на `/app/` — иначе точка входа залипнет в кеше
   вебвью. Проксирование в `api:8000` осталось общим.
5. URL Mini App в кабинете VK — `https://astrozvezdochet.ru/app/`,
   переключается ПОСЛЕ ручной проверки в живом VK.

Снос Jinja-стенда — отдельный шаг после этой проверки, не одновременно с ней
(`astro-context.md`, «Стенд снят, адреса разведены»). Оплата, юр. страницы,
админка и вебхуки остаются в `app/web/` и не трогаются вовсе.

## Верификация

- Локально: `npm run dev` + backend (`uv run uvicorn app.main:create_app`),
  прогон онбординг→разбор в браузере; затем через localhost.run из живого
  VK (подпись, прелоадер, ссылки).
- Пейволл: тестовый магазин ЮKassa (ключи ТОЛЬКО парой) — оплата во внешнем
  браузере, возврат в Mini App, разбор открылся.
- `pytest` backend зелёный (фронт его не трогает, кроме шага 10).
- После выкатки Vue на `/app/`: Jinja-стенд, `/admin`, `/pay/*` отвечают как
  раньше. После сноса стенда — то же, кроме самого стенда: корень отвечает
  редиректом, а `/admin`, `/pay/*` и юр. страницы не меняются.

## Риски

- `generation.state()` живёт в памяти процесса: рестарт api во время
  генерации покажет `available` вместо `running` — generic ReportView это
  переживает (повторный запуск берёт кеш, денег не тратит).
- `calc` — словарь с ключом `natal` (позже matrix/eastern): таблицы читают
  строго `calc.natal`, отсутствие ключа — скелетон, не падение.
- Пока URL в кабинете VK не переключён, фронт на проде никому не виден —
  выкатка безопасна.
