# План проекта: астро-сервис (целевая платформа — VK, обкатка на веб-стенде)

Рабочая гипотеза: аудитория ВК платит за персональные астрологические разборы (подтверждено ручным рынком «300 ₽ за совместимость»). Продукт — мгновенный AI-разбор по точному расчёту, красивее и глубже ручного, по той же цене.

## 1. Рамки MVP (1 месяц)

**Входит:**
- VK Mini App: онбординг → бесплатный разбор → платные отчёты
- Расчёты: натальная карта (планеты, дома, аспекты), Матрица Судьбы, восточный гороскоп
- Два платных продукта: полный разбор личности и совместимость пары
- Сайт как платёжный хаб (ЮKassa) + минимальный лендинг
- Виральность: инвайт-ссылка на совместимость, шеринг карточки в сторис

**Не входит (v1.1, месяц 2):**
- Подписка на ежедневные прогнозы + рассылки от сообщества
- Telegram Mini App (бот продолжает жить как есть)
- Собственный рендер колеса (на старте — SVG из kerykeion)

## 2. Архитектура

- **Монорепо:** `/backend` (FastAPI + модуль ядра), `/frontend` (Vue 3 + Vite), `/site` (лендинг + страница оплаты, можно та же Vue со своим роутом)
- **Backend:** FastAPI, SQLAlchemy 2 + Alembic, Postgres 16, pyswisseph + kerykeion, клиент DeepSeek, SDK ЮKassa, VK API клиент
- **Авторизация Mini App:** проверка `sign` из launch params (HMAC-SHA256 на секрете приложения) → JWT-сессия. Регистрации нет вообще.
- **Деплой:** Docker Compose (api, статика за Caddy/nginx, postgres). Можно на существующем VPS; альтернатива — VK Cloud (бонус 2500 ₽/мес по программе поддержки Mini Apps).

## 3. Модель данных

| Таблица | Ключевые поля |
|---|---|
| `users` | id, platform + external_id (уникальная пара — см. платформенный адаптер в astro-context.md), name, is_tester, free_reports_used, created_at |
| `charts` | id, user_id, kind (self/partner/relative), name, birth_date, birth_time, time_known, city, lat, lon, tz, calc JSONB |
| `reports` | id, chart_id, pair_chart_id (nullable), type (free_natal / full_natal / matrix / eastern), status, content, prompt_version, model, temperature, usage — последние три для корпуса генераций, из которого строится пост-фильтр текста |
| `orders` | id, user_id, report_type, chart_ids, amount, provider_id, status, paid_at |
| `events` | id, user_id, name, props JSONB, ts — своя аналитика воронки |
| `horoscopes` | sign, period, period_key (уникальная тройка), content — гороскоп на знак, а не на человека: для Овна он один на всех |
| `content_posts` | id, kind (daily/event/portrait/celebrity/invite), publish_at, body, status (draft/approved/published), vk_post_id — очередь постов сообщества |

Флаг «разрешил сообщения сообщества» живёт в `users`: это главная метрика
Mini App после отказа модерации (см. [vk-moderation.md](vk-moderation.md)).

Кеш отчётов: уникальность по (расчёт, тип, prompt_version) — одинаковые запросы не гоняются в LLM повторно.

### Решения по слою карт (`backend/app/services/charts.py`)

**Поиск города и создание карты — два отдельных вызова.** Соблазнительно
сделать одну функцию «дата + строка "Ростов" → карта». Так нельзя: Ростовов
два (Ростов-на-Дону и Ростов Великий), Ивановок — десятки; выбирает всегда
человек, и между поиском и расчётом обязан поместиться экран со списком.
Поэтому `search_places()` отдаёт варианты, а `create_chart()` принимает уже
выбранные координаты.

**Дубли карт ловим по `input_hash`, а не сравнением полей.** «Посчитай ещё
раз» не должно плодить копии: за каждой копией потянутся свои отчёты, то есть
лишние деньги за DeepSeek. Уникальная пара `(user_id, input_hash)` в базе
ловит дубль физически, а не «мы вроде проверили перед вставкой». Сравнение
пяти колонок вместо хеша ломается на float: 55.5 и 55.50000000000001 стали бы
разными городами. В хеш входит и флаг `time_known` — «родился ровно в 12:00»
и «время не помню» дают одинаковый расчёт, но это разные карты: во второй
нельзя показывать дома и промпт для неё другой. Координаты в хеше округляются
до 4 знаков (~11 м) — не ради точности, а ради стабильности: один и тот же
город из справочника и из формы иначе дал бы разные хеши.

**Подстановка полудня при неизвестном времени** живёт внутри `create_chart()`,
до вычисления хеша. Отдай это вызывающему — бот подставит 12:00, веб 00:00,
и одна карта запишется дважды.

## 4. Основные ручки API

- `POST /api/auth/vk` — проверка подписи, выдача JWT
- `POST /api/charts` — дата/время/город → геокодинг → расчёт → «астропаспорт» JSON
- `GET /api/charts/{id}` — расчёт + SVG колеса
- `POST /api/reports/{type}` — бесплатный генерируется сразу; платный — после оплаты
- `POST /api/orders` — создать заказ, вернуть ссылку на оплату
- `POST /api/webhooks/yookassa` — подтверждение платежа → разблокировка отчёта

## 5. Расчётное ядро

- **pyswisseph:** позиции планет, дома (Placidus по умолчанию), аспекты с орбисами
- **kerykeion** поверх — быстрый старт и SVG-колесо
- **Матрица Судьбы:** арифметика по дате рождения, реализуется по открытым описаниям за день
- **Восточный гороскоп:** китайский календарь (библиотека `cnlunar` или `lunardate`)
- **Геокодинг и таймзоны:** офлайн-база городов (GeoNames) + `timezonefinder`; исторические таймзоны считать по координатам и дате — частая ошибка конкурентов
- Выход ядра — единый JSON «астропаспорт»: идёт и в LLM, и на фронт
- **Обязательный тест:** сверка 10 эталонных дат с astro-seek до написания любого другого кода

## 6. LLM-слой

- DeepSeek; вход — JSON расчёта, выход — структурированный разбор по секциям
- Промпт на тип отчёта — Python-модуль в `app/llm/prompts/` (`VERSION`, `SYSTEM`, `build_user()`, у полного разбора ещё `parse()`); правятся в коде, из админки не редактируются
- Версионирование промптов (prompt_version в reports); `VERSION` бампается руками — без этого кеш отдаст старый текст под новой редакцией
- Тон: развлекательно-рефлексивный, без медицинских и фатальных предсказаний — важно и для модерации ВК, и по существу

## 7. Экраны Mini App

1. **Онбординг** — 3 шага (дата, время «не знаю точно» допустимо, город с подсказками); имя и дата рождения автоподставляются из `VKWebAppGetUserInfo`
2. **Моя карта** — колесо, табы: натал / матрица / восточный
3. **Разбор** — секции (личность, отношения, карьера, финансы, кармика); первая открыта, остальные под блюром с тизером
4. **Совместимость** — выбор из сохранённых карт или инвайт-ссылка партнёру
5. **Карты близких** — бесплатно 2, дальше платно
6. ~~**Пейволл**~~ — **экран подписки на сообщество** (правка 2026-08-20):
   цен, кнопок оплаты и ссылок на сайт в VK быть не может, на их месте —
   `VKWebAppJoinGroup` и `VKWebAppAllowMessagesFromGroup`
7. **Профиль** — данные рождения, покупки

## 8. Платежи

- ЮKassa на сайте: Mini App → кнопка → страница заказа (order token в URL) → оплата → вебхук → отчёт открыт
- Внутри Mini App цифровые товары продаются только за «голоса» с большой комиссией платформы — поэтому оплата всегда внешняя
- Юр. база: самозанятость (оформить в первую неделю, подключение ЮKassa занимает несколько дней)
- Цены MVP: полный разбор 490 ₽, совместимость 590 ₽, комплект 890 ₽

## 8.1 Контур сообщества VK (добавлено 2026-08-20)

Появился после отказа модерации: сообщество — звено между бесплатным
приложением и оплатой на сайте. Механика, контент-сетка и обоснования — в
[vk-moderation.md](vk-moderation.md), здесь только границы модулей.

| Модуль | Отвечает за | Не знает про |
|---|---|---|
| `astro_core/transits.py` | транзиты на дату, календарь событий (ретроградности, лунации, затмения, входы в знаки) | VK, LLM, базу |
| `app/services/content.py` | тексты постов из расчёта, очередь `content_posts` | VK |
| `app/vk/community.py` | `messages.send`, Callback API сообщества (`message_allow` / `message_deny`) | астрологию |

Правило границы то же, что у `bot/`: слой публикации знает про VK API и
ничего не знает про астрологию, расчётные и генерирующие модули — наоборот.
Иначе тот же гороскоп дня придётся писать заново для Telegram.

**Публикации постов в этом слое нет намеренно**: `wall.post` ключом
сообщества не вызывается (право `wall` есть только у пользовательского ключа
и выдаётся по запросу в поддержку VK), поэтому посты уходят в отложку VK
руками, а `content.py` доводит их только до состояния «готов к публикации».
Появится право — добавится один метод, границы не меняются.

Отдельным куском — **одноразовый токен связывания**: ссылка из рассылки
приводит VK-пользователя в браузер уже узнанным, иначе он платит анониму с
пустой cookie и вводит дату рождения заново.

## 10. Метрики решения (конец месяца)

| Метрика | Цель |
|---|---|
| Вход → построил карту | ≥ 60% |
| Карта → открыл пейволл | ≥ 30% |
| Пейволл → оплата (холодный трафик) | 2–5% |
| Возврат посева первой покупкой | ≥ 30% |

Если посев окупается на треть первым касанием — экономика сходится на повторных покупках, масштабируем. Если конверсия в карту низкая — чиним онбординг. Если в оплату — чиним пейволл и качество бесплатного разбора.

## 11. Риски

- **Модерация каталога ВК** — подавать заранее, тон «развлекательный сервис», без гарантий и обещаний
- **Реклама эзотерики запрещена в VK Ads** — трафик только посевами и виральностью, это заложено в план
- **Точность расчётов** — эталонные тесты с первого дня; ошибка в домах убивает доверие мгновенно
- **Затраты на LLM** — кеш отчётов + лимит бесплатных генераций на пользователя
- **Платформенный риск ВК** — ядро платформо-независимое; сайт и ТГ-бот остаются запасными фронтами
