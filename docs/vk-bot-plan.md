# VK-бот «Звездочёт» — как устроен

Чат-бот в сообщениях сообщества vk.ru/astrozvezdochet. Выкачен на прод,
работает при `VK_BOT_ENABLED=true`. Здесь то, что есть в коде, и решения,
которые легко отменить по незнанию. План задач 1–10 (31.10–04.11.2026)
выполнен; его история — в git.

---

## 1. Зачем

Mini App тяжёл для холодного человека из ленты: узкое место (аудит 31.10)
— переход из ленты в личку. Бот принимает его прямо в сообщениях
сообщества. Главная метрика — **15+ новых разрешений сообщений в неделю**
(`BOT_ALLOWED_GOAL` в `services/admin.py`).

## 2. Решения

- **Кодовые слова только `КАРТА` и `ПАРА`** — в личке и в комментариях.
  Регистр, пробелы и «ё» не важны (`router.normalize`).
- **`КАРТА` — бесплатный `free_natal` прямо в личке**, время рождения
  необязательно.
- **`ПАРА` и «Совместимость» — только кнопка в Mini App** (`open_app`,
  `hash="pair"`), без тизера в личке.
- **Бесплатная `КАРТА` и `ПАРА` — только подписчикам сообщества (13.11.2026).**
  Подробности — раздел 4, «Вход только подписчикам», и
  [astro-context.md](astro-context.md), «Бесплатное в боте — только
  подписчикам сообщества».
- **VIP-разбор продаётся и в боте** — та же цена из `orders.PRICES`, тот же
  `vip.create_order` и ссылка `/pay/order/<token>`, что у заказа из админки.
- **Гороскоп на сегодня** — письмо готовой рассылки `daily_horoscope`;
  **на месяц** — отдельный промпт `monthly_horoscope`. Оба бесплатно.
- **Рассылка через бота — только явное согласие (01.11.2026).** Новые
  пользователи бота создаются с `subscribed=False`; подписывают только кнопки
  «🔔 Подписаться» и «🔔 Гороскоп по утрам». Выбор знака и КАРТА не
  подписывают. Пользователи Mini App и VK ID создаются как раньше
  (`subscribed=True`): модель и `server_default` не тронуты, флаг передаёт
  только Callback.
- **В комментариях бот не отвечает (04.11.2026).** `wall.createComment`
  ключом сообщества — ошибка 15: права «стена» у ключа сообщества нет, а ключ
  администратора на сервере не держим. См. раздел 4, «Комментарии».

**Вне рамок:** гороскоп на год, пакеты разборов, Telegram и MAX (ядро
платформенно-независимое, но адаптеров нет), выбор времени рассылки, ответы
LLM на вопросы клиента.

## 3. Устройство

### 3.1 Файлы

```
backend/app/chatbot/          # ядро, про VK не знает
  types.py      # Incoming, Reply, Button/LinkButton/AppButton, Job, MemberCheck
  states.py     # имена состояний FSM
  texts.py      # все тексты и подписи кнопок
  router.py     # handle() и run_job()
  parse.py      # свободный ввод даты, времени, города (с падежом)
  storage.py    # bot_dialogs: load/save/reset; bot_events_seen: seen()
  flows/
    menu.py     # меню, знак, сегодня, месяц, подписка на рассылку
    natal.py    # КАРТА; тот же сбор данных использует VIP
    vip.py      # платный разбор
    gate.py     # вход только подписчикам для КАРТЫ и ПАРЫ
backend/app/vk/bot.py         # адаптер: message_new → ядро → messages.send
backend/app/vk/comments.py    # wall_reply_new: КАРТА/ПАРА под постом
backend/app/models/bot_dialog.py  # bot_dialogs, bot_events_seen, bot_comment_replies
```

ПАРА своего файла в `flows/` не имеет: это одна кнопка, она живёт в
`router._start_pair`.

**Граница слоёв.** `app/chatbot/` ничего не импортирует из `app/vk/`
(проверяет `test_router_does_not_import_app_vk`). Всё, что нужно ядру от
площадки, приходит снаружи: `Incoming` на входе и функция `is_member` для
проверки подписки.

### 3.2 Путь сообщения

1. `POST /vk/callback` (`web/routes/vk_callback.py`) проверяет `secret` и
   `group_id`, обновляет флаги разрешений, коммитит.
2. Если `vk_bot_enabled` и это личное `message_new` — `storage.seen(event_id)`
   (`INSERT … ON CONFLICT DO NOTHING`); повтор VK дальше не идёт. Событие без
   корректного `event_id` подтверждается, но диалог не запускает.
3. `background.add_task(bot.process_message, obj)`, ответ `"ok"` сразу.
4. `process_message` в своей сессии: `users.get_or_create(…, subscribed=False)`,
   событие `bot_ref` при метке, `router.handle(…, is_member=member_check(id))`,
   **коммит до отправки** — следующее сообщение уже относится к новому
   состоянию.
5. `bot.deliver` шлёт ответы. `Job` в списке ответов — долгая работа (разбор
   30–60 с): сначала уходит всё до неё («Считаю карту: …»), затем
   `router.run_job` в новой сессии, затем его ответы.

Фоновые задачи живут в памяти процесса: перезапуск между коммитом `event_id`
и концом отправки теряет ответ. Постоянной очереди нет. Зависший
`natal_wait` старше 5 минут даёт начать заново (`natal._WAIT_STALE`).

### 3.3 Порядок разбора в `router.handle`

сброс («меню», «начать», «старт», `command=start`, `cmd=menu`) → кнопка с
`cmd` → кодовое слово → обработчик текущего состояния → сообщение с датой
рождения в `idle` (КАРТА без кодового слова) → меню.

### 3.4 Отправка

- `keyboard_json`: обычная клавиатура (`one_time: false`) для меню, `inline`
  для кнопок под ответом. Лимиты VK: обычная — 10 рядов, inline — 6 рядов и
  **не больше 10 кнопок всего** (иначе ошибка 911). Отсюда выбор знака двумя
  сообщениями по 6 знаков.
- `split_text(limit=4000)` режет по абзацу, строке, слову; клавиатура — только
  у последней части. `strip_markdown` убирает `##` и `**`: личка их не рисует.
- `random_id` детерминирован от `(peer_id, conversation_message_id, номер
  части)` — повтор события не задвоит ответ.

### 3.5 Логирование

В лог — `user_id`, состояние, тип события и код ошибки VK. Никогда — текст
сообщения, дата, время, город: в исключении парсера может оказаться дата
рождения, поэтому у не-`VkError` пишется только тип.

### 3.6 Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `VK_BOT_ENABLED` | `false` | выключатель диалога и комментариев; флаги разрешений работают всегда. Без него нет и строки про бота в вечернем посте (`promo.sign_lines_footer`) |
| `VK_BOT_GATE_ENABLED` | `true` | КАРТА и ПАРА только подписчикам; `false` пускает всех |
| `VK_GROUP_ID`, `VK_APP_ID` | — | нужны кнопке `open_app` и `groups.isMember` |
| `VIP_OWNER_VK_ID` | — | кому писать про комментарии без разрешения и про оплату VIP |

## 4. Сценарии

### Меню

Обычная клавиатура внизу экрана, без inline-копии под сообщением:

| Ряд | Кнопки |
|---|---|
| 1 | «🔮 Гороскоп дня», «📅 На месяц» |
| 2 | «🌟 Натальная карта» (КАРТА), «💞 Совместимость» (ПАРА) |
| 3 | «♈ Мой знак», «🔔 Подписаться» / «🔕 Отписаться» |
| 4 | «💫 Разбор с астрологом» (VIP) |

Подписи короткие: на телефоне две кнопки в ряд обрезают текст после ~14
знаков. В VK на компьютере нижняя клавиатура иногда не рисуется.

### Знак

12 кнопок «♈ Овен» по два в ряд, двумя сообщениями, плюс «Ввести дату
рождения». В день смены знака — две кнопки соседних знаков. Знак, выбранный
вручную (`users.sun_sign`), важнее знака из карты. Выбор знака не подписывает
на рассылку, только предлагает кнопку.

### Гороскоп на сегодня и на месяц

Сегодня — письмо знака из `broadcast.letters_for(сегодня по МСК)`, то же, что
ушло рассылкой. Месяц — из поста `monthly_horoscope` за 1-е число; пишет его
`scripts/monthly_cli.py` по cron 1-го числа (`deploy/monthly.sh`). Нет поста
— «ещё готовится» и меню. Знака нет — сначала выбор знака, потом сразу
гороскоп (`pending` в `data`).

### Подписка на рассылку

«Подписаться» без знака — сначала выбор знака: рассылка без знака ничего не
пришлёт. «Отписаться» выключает `subscribed`, разрешение VK на сообщения не
трогает.

### Вход только подписчикам (`flows/gate.py`)

- Проверка `groups.isMember` **до первого вопроса** — на кодовом слове,
  кнопке меню, комментарии и сообщении с датой. Человек, который ввёл дату,
  время и город и только потом увидел «подпишись», уходит совсем.
- **Каждый раз заново, без кеша.** Отписался — следующий расчёт снова
  попросит подписку; выданное остаётся у человека.
- Не подписан — текст и две кнопки: «Подписаться на „Звездочёт“» (ссылка на
  сообщество; не «Подписаться» — так в меню называется рассылка) и «✅ Я
  подписался». Вторая проверяет снова и продолжает с уже присланных данных:
  сообщение, на котором остановил гейт, лежит в `data.gate.text` (до 500
  знаков).
- **VK не ответил (`None`) — пропускаем**: потерять человека из-за сбоя VK
  дороже одного разбора.
- **VIP не закрыт.** **Mini App не закрыт** — по прямой ссылке разбор и пара
  доступны без подписки.
- Старая кнопка «Повторить» под давней ошибкой разбора запускает КАРТУ мимо
  гейта — случай редкий, оставлен.

### КАРТА

Порядок вопросов не жёсткий: каждое сообщение `parse.parse_birth` разбирает
целиком (дата в любой записи, время или «не помню», город с падежом — «в
Егорьевске»), бот спрашивает только недостающее. «КАРТА 9.03.1987
Егорьевск» тоже работает. Единственное совпадение города в RU берётся без
переспроса, иначе — до 5 кнопок и «Другой город».

Дальше `natal_wait` → «Считаю карту: …» → `Job`: `charts.create_chart`,
коммит карты и событий **до LLM** (падение генерации их не откатит),
`reports.get_or_create_report`. Ответ — текст с шапкой «Натальная карта: …»
и кнопками «Полный разбор» (VIP, без цены — она на следующем экране) и «🔔
Гороскоп по утрам» неподписанному. Отказ лимита — «на сегодня разборы
закончились», авария LLM — «Повторить». Данные рождения остаются в
`data.last`: по ним VIP не спрашивает заново.

### VIP

Вход — «Полный разбор» под разбором или «💫 Разбор с астрологом» в меню.
Описание с ценой → «Оформить за N ₽» → данные из `data.last` или тот же сбор,
что у КАРТЫ (`purpose=vip`) → имя (можно пропустить) → род обращения →
сводка «Всё верно» / «Исправить» → `vip.create_order` → кнопка «Оплатить».
Нет ссылки оплаты — «напиши сюда», владелец видит заказ в `/admin/vip`. Уже
оплачено по этой карте — кнопки оплаты нет. Дальше всё как у заказа из
админки: вебхук ЮKassa → `notify_paid` → черновик и отправка с карточки.

### ПАРА

Текст и inline-кнопка `open_app` на `#pair` — экран создания пары в Mini App.
Событие `bot_pair_link`. Ref внутри hash не передаём: `parseGoal` во фронте
такую строку не поймёт; VK сам ставит `vk_ref=bot_keyboard`.

### Комментарии (`vk/comments.py`)

Ветка `wall_reply_new` в Callback стоит **до логики разрешений**:
комментарий согласием на переписку не является, а рассылка без согласия —
бан сообщества.

- КАРТА/ПАРА под постом, разрешение писать есть (`vk_messages_allowed_at` и
  нет `bot_blocked_at`) → «Увидела твой комментарий…» и сценарий ядра в
  личке. `messages.isMessagesFromGroupAllowed` не зовём: разрешение берём
  только из своей базы.
- Разрешения нет → в комментарии тишина, владельцу в личку — кто, какое
  слово и ссылка на комментарий. Одно уведомление на человека и пост (по
  событию `bot_comment_no_dm`). Отказ VK — следующий комментарий попробует
  снова.

### Ref-метки

`vk.me/astrozvezdochet?ref=<метка>` → событие `bot_ref` с `ref` и
`ref_source`; `users.source` не трогаем (Callback уже записал `vk_group`).
Метки: `evening_<ГГГГММДД>` в вечернем посте `sign_lines` (дата гороскопа —
номер записи до ручной публикации неизвестен), `morning` в утреннем
`daily_sky`.

## 5. Хранение

**`bot_dialogs`** — строка на человека: `state` и `data` (JSONB).

Состояния: `idle`, `ask_sign`, `natal_date`, `natal_time`, `natal_city`,
`natal_city_pick`, `natal_wait`, `vip_name`, `vip_gender`, `vip_confirm`.

Ключи `data`:

| Ключ | Чей | Что |
|---|---|---|
| `purpose` | natal | `free` или `vip` — куда идти после сбора |
| `date`, `time`, `time_known`, `place`, `places` | natal | черновик данных рождения и варианты города |
| `last` | natal → vip | данные последней КАРТЫ; переживает сброс черновика |
| `name`, `gender` | vip | имя и род обращения |
| `pending`, `mode` | menu | что сделать после выбора знака; ввод даты или выбор на границе знаков |
| `gate` | gate | `target` и сообщение, на котором остановил гейт |

**`bot_events_seen`** — `event_id` уже обработанных событий Callback.
Чистки в коде нет; ориентир — выкидывать старше 7 дней, на разборы и оплату
это не влияет.

**`bot_comment_replies`** — **не используется.** Заводилась под антиспам
ответов под комментарием, которых не будет (ошибка 15). Оставлена на случай
ключа с правом «стена»; модель и миграция `b7e2c4a91f03` на месте.

Схема и каскады — [db-schema.md](db-schema.md).

## 6. События и воронка

| Событие | Когда |
|---|---|
| `gate_shown` | не подписан — показана просьба; `target` = `natal` / `pair` |
| `gate_passed` | подписался после просьбы и прошёл; `target` |
| `bot_natal_started` | начата бесплатная КАРТА |
| `bot_vip_shown` | открыто описание VIP |
| `bot_pair_link` | выдана кнопка в Mini App на пару |
| `bot_ref` | пришёл по ссылке с `ref` |
| `bot_today_shown`, `bot_month_shown` | отдан гороскоп; в props знак |
| `bot_comment_to_dm` | КАРТА/ПАРА в комментарии ушла в личку |
| `bot_comment_no_dm` | писать нельзя — уведомлён владелец |

Плюс общие: `chart_created`, `report_*`, `order_created`, `order_paid`,
`group_messages_allowed`, `group_message_received`.

`/admin/funnel`, блок «VK-бот по неделям» — **по неделе события, а не
когортой**: разрешили писать (цель 15), написали боту, КАРТА начата и
готова, увидели VIP, заказ, оплата, комментарий → личка / владельцу.
`report_ready` и `order_*` пишут и Mini App, и сайт, поэтому засчитываются
только люди с событием бота в ту же неделю. Отдельно — «Откуда пришли в
бота» по `ref`. Столбцов под `gate_*` пока нет.

## 7. Эксплуатация

- **Кабинет сообщества:** в Callback API включены `message_new`,
  `message_allow`, `message_deny`, `wall_reply_new`; включены «Возможности
  ботов» — без них клавиатуры падают с ошибкой 912. Ключ сообщества с правом
  `messages`, без «стены».
- **Строка подтверждения Callback** живёт в `VK_CALLBACK_CONFIRMATION`; VK её
  меняет — бот молча перестаёт отвечать, пока строку не обновить.
- **Сервер в Europe/Berlin:** cron 06:00 — это 08:00 МСК. Даты «сегодня» и
  месяц бот считает по Москве (`content.today_msk`).
- **Гороскоп на месяц** — cron 1-го числа, `deploy/monthly.sh`; забыли — бот
  отвечает «готовится», ошибки не видно.

## 8. Открытые хвосты

- Не подтверждено вживую: приходит ли `message.ref` из `vk.me/…?ref=` и
  доходит ли `wall_reply_new` до нашего Callback.
- Первая боевая оплата VIP из бота не проходила (общий пункт
  [progress.md](progress.md)).
- Ответ теряется при перезапуске процесса посреди отправки (раздел 3.2).
- `bot_events_seen` растёт без чистки.
- Гейт подписки не выведен на `/admin/funnel` — смотреть запросом в `events`.
