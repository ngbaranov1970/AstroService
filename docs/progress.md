### Зафиксированные решения

- **Узел**: считаем истинный (true node); astro-seek в основной таблице
  показывает средний — расхождение до ~1.5° это норма, не баг.
- **Lilith, Fortune, Vertex** не считаем (пока не нужны продукту).
- **Аспекты** с astro-seek не сверяем — у них другие орбы по умолчанию,
  списки законно различаются.
- **Округление**: мы округляем минуты дуги, astro-seek усекает — наши минуты
  систематически на +1' больше, реальная разница — доли минуты.
- `cities.txt` коммитим в git (4.8 МБ, нужен для работы и тестов);
  исходные zip GeoNames и кеш astro-seek — в .gitignore.

## Как запустить

Окружение одно на весь репозиторий; команды запускаются из папки своего
проекта, uv сам находит корень workspace вверх по дереву.

```bash
# из корня репозитория: поставить зависимости обоих проектов
uv sync --all-packages --extra dev

cd backend

# если backend/data/cities.txt отсутствует:
uv run python scripts/build_cities.py

# тесты (56 шт: золотые карты, календарь транзитов, промпты, рассылка):
uv run --extra dev pytest

# база: накатить схему (нужен работающий Postgres и заполненный .env)
uv run alembic upgrade head

# сверить модели с базой — молчаливое "No new upgrade operations detected"
# означает, что код и база совпали; любой вывод операций = забыли миграцию
uv run alembic check

# новая миграция после правки app/models/ (файл потом ВЫЧИТАТЬ руками —
# autogenerate не видит переименований и хуже всего справляется с данными):
uv run alembic revision --autogenerate -m "что изменили"

# посчитать карту руками:
uv run python scripts/natal_cli.py 1990-05-11 17:20 Касимов

# рассылка гороскопа дня (то же, что кнопка в /admin/broadcast):
uv run python scripts/broadcast_cli.py --dry-run     # охват, без отправки
uv run python scripts/broadcast_cli.py               # за сегодня по Москве
uv run python scripts/broadcast_cli.py --date 2026-08-25

# сверить дату с astro-seek и записать новый эталон:
uv run python scripts/seek_check.py 1993-02-01 12:00 Пермь
uv run python scripts/natal_cli.py 1993-02-01 12:00 Пермь --json > tests/golden/1993-02-01_perm.json
```

## Решения по стратегии

Порядок работ после модерации (решение 27.08): **Vue-фронт → совместимость →
сообщество параллельно → монетизация неагрессивно**. Обоснование — в
[astro-context.md](astro-context.md), «Где мы сейчас». Следствия для кода,
которые надо держать в голове:

- в `users` — пара `(platform, external_id)` вместо `vk_id`, плюс `is_tester`
  (тестерам открыт полный разбор без оплаты). Веб-пользователь — это
  `platform='web'` и случайный UUID в cookie: пара для того и заведена;
- **все генерации логируются** (текст, `prompt_version`, модель, temperature,
  usage) — из этого корпуса потом строится пост-фильтр текста, без которого
  на модерацию VK идти нельзя;
- веб-стенд дёргает `app/services/*` напрямую, теми же вызовами, что позже
  будет дёргать бот. `app/api/*` (JSON для Mini App) не трогаем — стенд
  отдаёт HTML, это отдельный слой `app/web/`;
- граница из CLAUDE.md действует и здесь: в `app/services/*` не должно быть
  ни объектов aiogram, ни объектов FastAPI (`Request`, `Response`). Сервис
  принимает данные и сессию, возвращает модели.

Решение 2026-07-24 в силе: сначала натальная ветка до продукта, Матрица Судьбы
и восточный гороскоп — после.

Прежний порядок держался на доводе «пока идёт ревью VK, трогать нельзя ни URL
приложения, ни домен». **С 27.08 довод снят целиком**: модерация закончилась,
пункты 1–4 закрыты, сообщество ведётся, рассылка уходит по расписанию.

Очередь после модерации (утверждена 27.08, уточнена 01.09):

1. ~~**Переезд на `astrozvezdochet.ru`**~~ — СДЕЛАНО 28.08;
2. ~~**Снос стенда**~~ — СДЕЛАНО 01.09: подписка на сообщения сообщества и
   отзывы перенесены в `/api/v1`, `stand.py` с шаблонами и `forms.py`
   удалены, корень отвечает 302 в `/app/`, `/r/<token>` — 301 в
   `/app/#/chart/<token>`. Признак тестера (`?t=` ушёл вместе со стендом)
   теперь ставится кнопкой в таблице `/admin`;
3. **Выкатка Vue на `/app/`** и проверка в живом VK. Порядок вышел обратным
   задуманному: стенд снят раньше, чем Vue проверен, и отката на рабочий
   интерфейс больше нет. Значит прогон через туннель обязателен ДО деплоя,
   а не после него. Фронт функционально готов целиком (01.09) — ждёт
   именно прогона. Перед деплоем сверить прод-`.env`: без `VK_GROUP_ID`
   блок сообщества не появится и в VK, и это будет выглядеть поломкой
   вёрстки. `WEB_TESTER_TOKEN` оттуда можно удалить — код его больше
   не читает;
4. **VK ID как веб-вход** — без него браузерный заход в приложение
   невозможен: `POST /api/v1/auth/web` в проде отвечает 404. Заодно исчезает
   отдельная веб-личность (`astro-context.md`, «Идентичность пользователя»);
5. **Лендинг на корне** — одна Jinja-страница рядом с юридическими, заменяет
   собой редирект из пункта 3;
6. **Совместимость** — единственная новая функция. Она требует второго
   человека и потому сама даёт повод переслать ссылку, а купить трафик нельзя
   (реклама эзотерики в VK Ads запрещена);
7. **Монетизация** — последней и неагрессивно. Платный трафик на сырую
   витрину даёт число, которое нельзя интерпретировать.

контент и читателей, на которых проверяется качество текстов. Знакомые для
этого не годятся — хвалят из вежливости.
