## Где мы сейчас

**Прод живёт на `astrozvezdochet.ru`.** Отдаются JSON-API `/api/v1`,
Vue-приложение на `/app/`, лендинг на корне и Jinja-страницы: оплата,
юридические, админка.
Старый `ngbaranov.top` и `www` отвечают 301 с сохранением пути, `/r/<token>`
из уже выданных разборов ведёт в `/app/#/chart/<token>` — цепочка ссылок
сохранена целиком. Бэкап базы по cron в 3:30, восстановление проверено.

**Входов два, площадка едет в токене.** Из VK личность приходит подписью
launch params, из браузера — через VK ID (`/auth/vkid/start` → `id.vk.ru`,
OAuth 2.1 + PKCE). Отдельной веб-личности не появляется: VK ID отдаёт тот же
`vk_user_id`, что launch params. Различает площадки не `users.platform`, а
`SURFACE_VK` / `SURFACE_WEB` в токене — иначе браузерному заходу в VK-строку
закрылась бы оплата. Cookie-вход `POST /api/v1/auth/web` остался только для
отладки вёрстки и в проде отвечает 404.

**Лендинг стоит на корне (07.09.2026).** Одна Jinja-страница в дизайне
приложения: колесо эталонной карты 1990-05-11, три факта о точности, три шага,
образец расчёта таблицей, фрагмент разбора и состав платного — названия частей
приходят из `SECTION_TITLES` промпта, а не переписаны в шаблон. Корень при
этом остался развилкой: `sign` или `vk_*` в адресе → 302 в `/app/` со всей
query, иначе страница (разбор — в [astro-context.md](astro-context.md),
«Корень домена — развилка»).

**Фронт закрывает весь функционал бывшего стенда.** Работают онбординг,
главная, экран разбора со всеми пятью состояниями и поллингом генерации,
выход на полный разбор, переключатель карт, экран карты с таблицами планет,
углов с домами и аспектов, профиль с юридическим блоком, оценка разбора
звёздами и блок сообщества. Стенда нет нигде. Блок сообщества требует трёх
условий сразу — запуск из VK, `bridge.isEmbedded()` и непустой `VK_GROUP_ID`
на сервере; в обычном браузере он не рисуется, и это не поломка.

Сверх стенда во фронте — пять экранов совместимости (список пар, сборка,
пара, парный разбор, анонимное приглашение). Плиток-анонсов на главной больше
нет (20.09): обещания «скоро» под работающими разборами уводили внимание от
того, что уже можно купить.

**Совместимость сделана и продаётся.** Раздел закрыт целиком, от расчёта до
экранов, и выкачен на прод: `astro_core/synastry.py` считает межкартные
аспекты от двух готовых `charts.calc["natal"]` (сверено с astro-seek — 24
позиции в пределах 0,011°, все 43 аспекта совпали), таблица `pairs` хранит
расчёт пары, `pair_free` отдаёт бесплатный тизер, `pair_full` — платный разбор
за 390 ₽. Партнёр входит либо картой из своих, либо ручным вводом, либо по
анонимной инвайт-ссылке (`/invite/<token>`, экран без авторизации). Разбор
решений — в [astro-context.md](astro-context.md), «Синастрия» и «Пара: доступ,
инвайт и оплата»; схема хранения — в [db-schema.md](db-schema.md), экраны — в
[frontend-plan.md](frontend-plan.md), правила промптов — в
[astro-prompts-v2.md](astro-prompts-v2.md), раздел 8.

**Оплата работает на боевых ключах с 20.09.2026, магазин ЮKassa — 1448044.**
Через боевой магазин прошли четыре платежа (два `full_natal` по 290 ₽, два
`pair_full` по 390 ₽), цепочка заказ → уведомление → генерация → выдача
проверена целиком; повтор уведомления второй генерации не вызывает. Всё, что
оплачено до 20.09, шло через тестовый магазин 1436737. Смену ключей связка
переживает: платёж, заведённый при других ключах, ЮKassa отдаёт как 404, и
`sync_status` закрывает такой заказ как `CANCELED` вместо вечного `PENDING`.

**Сообщество ведётся, публикация ручная.** Генератор `app/services/content.py`
собирает тексты из календаря событий в таблицу `posts`, экран
`/admin/content` их показывает, публикация — через отложку VK (`wall.post`
групповым ключом не вызывается). В ленту идёт `daily_sky_v6` — обзор неба
суток одним текстом с концовкой «Стоит / Подождёт», к нему картинка 1080×1080
от `app/services/card.py`: главное событие суток и та же концовка поста
(с 25.09.2026, v6 пишет её без астрологических слов, чтобы влезла). Приписка про приложение выбирается случайно из
пяти формулировок (`promo.py`, зерно — `post.id`). **Второй, вечерний пост —
`sign_lines`**: гороскоп на завтра строкой на знак и приглашение в рассылку
(astro-context.md, «Контур сообщества VK»). Генератор пишет его на
`start+1 … start+7`, вычитка — своя вкладка `/admin/content/evening`, окно 8
дней. v1 выкачен 27.09.2026 и забракован: Лев шесть дней подряд получал
«Марс с Юпитером в твоём знаке». v2 (без планет, грань темы и форма фразы по
дням, запретов только два — здоровье и смерть) вычитан на 28.09–01.10. Все
посты sign_lines на проде удалены 27.09 (v1 и промежуточный v2), неделю
пишет заново текущий промпт. Рассылка гороскопа дня —
свой формат `daily_horoscope_v6`, двенадцать знаков, уходит в личные
сообщения по cron в 06:00 серверного времени.

**Расчётное ядро сверено.** Натальная карта — золотыми тестами против
astro-seek (10 эталонов). Календарь событий `astro_core/transits.py` —
перекрёстно с `natal.py` (расхождение 0,17″ при пороге 60″), с публичными
эталонами затмений и лунаций 2026 (в пределах 5 минут) и по равноденствиям.
Синастрия — независимым пересчётом перебором, тестом симметрии сторон и
ручной сверкой полной таблицы с astro-seek, плюс три эталона в
`tests/golden/synastry/`. Весь `pytest` — 270 passed.

**Каталога VK не будет.** Приложение одобрено на всех площадках (Android,
iOS, Mob.Web, Web), но «для распространения по прямой ссылке вне каталога»:
тематика признана узконаправленной. Оно доступно всем пользователям VK, но
органического потока из каталога нет. Разбор последствий — в
[astro-context.md](astro-context.md), «Где мы сейчас».

**Платный трафик пошёл: в VK Ads идёт таргет на подписку в сообщество,
450 ₽ в сутки с 20 по 27 сентября 2026** (3600 ₽ за восемь дней). Креатив
«переодетый» — рекламируется сообщество и его контент, без слов про астрологию
и услуги: прямая реклама эзотерики в VK Ads запрещена и модерацию не проходит.
Это первый холодный трафик у проекта, поэтому оценки конверсии впервые есть на
чём считать. **27.09 кампания кончается — к этому дню нужны цифры по каждому
переходу воронки, а не общее впечатление.** Решение и рамки — в
[astro-context.md](astro-context.md), «Платный трафик: переодетый креатив».

**Замер на старте кампании, 21.09.2026 06:35 МСК** — точка отсчёта, с которой
27.09 сравнивается результат:

| Что | На 21.09 | Чем смотреть |
|---|---|---|
| Пользователи | 69 (22 из VK, 47 из веба) | `users`, колонка `platform` |
| Разрешили сообщения | 10 | `users.vk_messages_allowed_at is not null` |
| Карты | 70 | `charts` |
| Пары | 13 | `pairs` |
| Отчёты | 104: 54 `free_natal`, 37 `full_natal`, 10 `pair_full`, 3 `pair_free` | `reports` по `type` |
| Оплаченные заказы | 28 на 8 920 ₽, боевых из них 4 на 1 360 ₽ | `orders where status='paid'` |

Три оговорки, без которых дельта соврёт. **Почти весь этот объём — свой и
знакомых**: холодного трафика до 20.09 не было вовсе, а 24 «оплаты» из 28
прошли через тестовый магазин и деньгами не являются. **Прироста подписчиков
сообщества в нашей базе не видно** — у нас только те, кто дошёл до приложения
или разрешил сообщения (те самые 10, они же охват рассылки), сами подписки
живут в кабинете VK. **Строка в `users` заводится при первом заходе в
приложение, а не при показе рекламы** — между подпиской и ею лежит вся лента
сообщества, поэтому нулевой прирост пользователей в первые дни кампании ещё
ничего не говорит о её провале.

**Воронку стало чем читать (22.09.2026).** Экран `/admin/funnel`: три
воронки — VK, сайт, пара — по **когорте** пришедших за период. Когорта это
те, чей первый `app_opened` попал в период; шаги засчитываются любой
давности, иначе открывший 21-го и заплативший 25-го выпал бы из счёта.
Считаются люди (`COUNT(DISTINCT user_id)`), а не события: три карты одного
человека — один дошедший. Тестеры скрыты по умолчанию, галочка их
возвращает. Отдельным блоком, без когорты, идут приглашения (у
`pair_invite_opened` нет `user_id` — экран анонимный), аварии и отказы
генерации, охват рассылки. Выборки — `services/admin.build_funnels` и
`count_events`, маршрут и подписи — `web/routes/admin.funnel`.

Две ловушки этого счёта, обе уже учтены и обе переживут рефакторинг, только
если о них помнить. **Площадка берётся из `props.platform` первого захода и
сравнивается с `"web"` точно**: это наша метка из `routes/vkid.py`, а VK
присылает `mobile_android`, `mobile_iphone`, `mobile_web`, `desktop_web` —
проверка «содержит web» утащила бы половину VK в веб-воронку; по
`users.platform` не разделить вовсе, VK ID отдаёт тот же `vk_user_id`.
**Вид разбора лежит в разных ключах**: у `report_*` это `type`, у `order_*` —
`report_type`, свести к одному нельзя, строки в базе уже написаны.
Ступени показа блока сообщества в воронке нет намеренно — причина у
константы `GROUP_OFFER_SHOWN` в `services/events.py`.

Отложены осознанно: бот и Telegram Web App, Матрица Судьбы и восточный
гороскоп, SVG-колесо, пост-фильтр LLM-текстов, автопостинг (нет права `wall`).

## Открытые хвосты

То, что не поломано, но выстрелит, если забыть.

- **Ключи ЮKassa меняются только парой** `shopId` + секретный ключ: ключ от
  чужого магазина даёт 401 на каждый запрос, а уже заведённые `pending`-заказы
  после смены закрываются как `CANCELED`. Сейчас на проде боевой 1448044,
  тестовый — 1436737.
- **Один платный парный разбор из девяти выходит безличным** — без обращения
  на «ты». Дефект известен с приёмки промптов `pair_full`, воспроизводится
  редко и лечится не запретом в тексте промпта, а входными данными (см.
  «Правило для промптов» ниже).
- **Луна при неизвестном времени плавает до ±6,5°.** С 24.09.2026 натальные
  промпты без времени не получают углов, домов и аспектов к углам
  (`time_known` в `build_user`), но Луна считается от того же подставленного
  12:00. У границы знака её знак может оказаться чужим, орбы лунных аспектов
  неточны. Разборы по 9 картам без времени, выданные до 24.09, остались
  старыми, с домами от полудня: все карты тестовые, перегенерировать не стали.
- **`VK_GROUP_ID` в прод-`.env` обязателен и задан там дважды.** Без него не
  появится блок сообщества даже внутри VK, и это выглядит поломкой вёрстки.
  Дубль строки ничего не ломает (побеждает последняя), но правка одной из двух
  значение молча не изменит — лишнюю убрать.
- **В `.env.example` не закоммичено удаление `WEB_TESTER_TOKEN`.** Переменной
  в `config.py` давно нет (тестер включается кнопкой в админке), пример
  обещает несуществующую настройку — правка лежит в рабочем дереве.
- **Отправка рассылки автоматическая, генерация постов — нет.** Если неделя
  не прогнана на `/admin/content`, cron пишет в `~/logs/broadcast.log` строку
  `FAIL` вместо письма. Признак забытого прогона — тишина у подписчиков, а не
  заметная ошибка, поэтому лог смотреть.
- **`astro_core/passport.py` написан, но не подключён.** Агрегатор «единый
  JSON для LLM и фронта» готов (`build_passport`, `Person`,
  `PASSPORT_VERSION`), но его не зовёт никто: `services/charts.py` кладёт в
  `calc` результат `compute_natal` напрямую, на фронт едет `calc["natal"]`.
  Подключать вместе с Матрицей и восточным — ради них он и писался. До тех
  пор это мёртвый код, о котором надо помнить, чтобы не написать второй такой же.
- **Шероховатости `daily_horoscope`, оставленные по решению «пока сойдёт»**:
  абзац перечисляет по четыре дома подряд и читается технично (лечится лимитом
  «два-три положения на абзац»), модель иногда пересказывает служебную строку
  («Планет в твоём знаке нет, но это не значит, что день пустой»).
- **У лендинга нет `og:image`** — превью ссылки в мессенджерах и VK выходит
  без картинки, а пересылаемая ссылка это половина смысла страницы. Рисовать
  нечем не с нуля: `services/card.py` уже делает PNG 1080×1080 к постам.
- **Лендинг и юридические страницы в разных палитрах.** Лендинг в цветах
  приложения (`#171310`, золото), `/pricing` и оферта — в старой
  сине-фиолетовой из `style.css`: переход из подвала меняет фон. Перекраску
  отложили сознательно, `style.css` общий с админкой.
- **Числа эталонной карты на лендинге дублируются** — таблица в
  `templates/landing.html` и массив в `static/landing.js`. Меняете эталон —
  меняйте оба места, комментарий об этом стоит в обоих файлах.
- **Сравнивать поколения промпта на `/admin/content` неудобно** — версии идут
  вертикально одинаковыми карточками, версия видна только в мелкой строке
  метаданных. Напрашивается версия в заголовке или колонки, как в
  `/admin/compare`.
- **Рассылка ждёт решения по монетизации** — что отдаём в ней бесплатно и как
  продавать, если внутри VK платить нельзя ([astro-context.md](astro-context.md),
  «Что даём в рассылке бесплатно»).
- **VK переехал с `.com` на `.ru` — у нас закрыто 27.09.2026** (дедлайн VK
  для API — 30.09.2026). `BASE_URL` в `app/vk/api.py` — `api.vk.ru`, VK ID —
  `id.vk.ru`, ссылки на приложение — `vk.ru/app<id>`. В коде `vk.com` не
  осталось; новые адреса VK писать только на `.ru`.
- **Удаления персональных данных по просьбе в коде нет.** Схема под него
  готова (`users.deleted_at`, каскады, RESTRICT у заказов), а функции,
  которая ставит `deleted_at`, нет — есть только обратная,
  `_revive_if_deleted` в `services/users.py`. Попросит человек — удалять
  руками в psql по шагам из [db-schema.md](db-schema.md) (конец раздела
  «Места, где схема неочевидна»): `deleted_at = now()`, `name = NULL`,
  `sun_sign = NULL`, затем `DELETE FROM charts WHERE user_id = …`. Кнопку в
  профиле и сервис делать, когда просьбы станут не единичными; список
  обнуляемых полей брать оттуда же, а не из памяти.

## Правило для промптов

**Запрет словами не работает, работает подстановка данных.** Проверено
шестью поколениями промпта гороскопа: «не выдумывай знак планеты» модель
нарушала при каждом прогоне, а список «что стоит в знаке читателя» с честным
«нет планет» снял ошибку до нуля с первого раза. То же с домами: пока сводку
получали три планеты из десяти, про остальные модель считала сама и всегда
мимо; строка на каждую планету закрыла вопрос.

Обратная сторона — данные сильнее правил и во вред: сводка по десяти планетам
без лимита на упоминания превратила абзац в перечисление четырёх домов подряд.

Приёмка парных промптов добавила к этому три механизма, которыми промпт
портит текст сам: образец хорошей фразы копируется дословно, ярлык блока
SYSTEM утекает читателю, служебные числа цитируются и запретом не лечатся.
Замеры и лечение — в [astro-prompts-v2.md](astro-prompts-v2.md), раздел 7.

## Карта кода

Здесь только «что где лежит». **«Почему так» живёт в docstring самого
модуля** — они подробные, и пересказ здесь неизбежно разъедется с кодом.
Решения, которые шире одного файла, — в [astro-context.md](astro-context.md).

**Расчётное ядро** `backend/astro_core/` — чистые функции, ничего не знают ни
про базу, ни про HTTP, ни про платформы:

| Файл | За что отвечает |
|---|---|
| `geo.py` | офлайн-геокодинг (~70 тыс. городов GeoNames в памяти) и таймзоны по координатам |
| `natal.py` | натальная карта на kerykeion 5: планеты, углы, дома Placidus, аспекты |
| `transits.py` | календарь астрособытий и небо суток (`day_sky`) для гороскопа |
| `synastry.py` | межкартные аспекты пары от двух готовых `calc["natal"]`, свои орбы и веса отбора |
| `passport.py` | агрегатор «единый JSON» — написан, но не подключён (см. «Открытые хвосты») |
| `matrix.py`, `eastern.py`, `wheel.py` | пустые файлы-заглушки, кода нет |

**Данные:**

| Файл | За что отвечает |

### Зафиксированные решения по расчётам

- **Узел**: считаем истинный (true node); astro-seek в основной таблице
  показывает средний — расхождение до ~1.5° это норма, не баг.
- **Lilith, Fortune, Vertex** не считаем (пока не нужны продукту).
- **Аспекты** с astro-seek не сверяем — у них другие орбы по умолчанию,
  списки законно различаются.
- **Округление**: мы округляем минуты дуги, astro-seek усекает — наши минуты
  систематически на +1' больше, реальная разница — доли минуты.
- `cities.txt` коммитим в git (4.8 МБ, нужен для работы и тестов);
  исходные zip GeoNames и кеш astro-seek — в .gitignore.
- Решение 2026-07-24 в силе: сначала натальная ветка до продукта, Матрица
  Судьбы и восточный гороскоп — после.

## Как запустить

Окружение одно на весь репозиторий; команды запускаются из папки своего
проекта, uv сам находит корень workspace вверх по дереву.

```bash
# из корня репозитория: поставить зависимости обоих проектов
uv sync --all-packages --extra dev

cd backend

# если backend/data/cities.txt отсутствует:
uv run python scripts/build_cities.py

# тесты (270 шт: синастрия, транзиты, рассылка, промпты, золотые карты, VK ID):
uv run --extra dev pytest

# база: накатить схему (нужен работающий Postgres и заполненный .env)
uv run alembic upgrade head

# сверить модели с базой — молчаливое "No new upgrade operations detected"
# означает, что код и база совпали; любой вывод операций = забыли миграцию
uv run alembic check

# новая миграция после правки app/models/ (файл потом ВЫЧИТАТЬ руками —
# autogenerate не видит переименований и хуже всего справляется с данными):
uv run alembic revision --autogenerate -m "что изменили"

# посчитать карту руками:
uv run python scripts/natal_cli.py 1990-05-11 17:20 Касимов

# натальный текст мимо базы и кеша; время «-» — неизвестно:
uv run python scripts/report_cli.py 1990-05-11 17:20 Касимов --prompt full_natal
uv run python scripts/report_cli.py 1990-05-11 - Касимов --prompt free_natal

# таблица синастрии по двум датам (--json пишет эталон):
uv run python scripts/synastry_cli.py 1990-05-11 17:20 Касимов 1992-01-10 04:30 Москва

# парный текст мимо базы и кеша — для приёмки промптов (--runs 3 даёт три
# разных прогона на одной паре, чего pair_cli.py из-за кеша не умеет):
uv run python scripts/pair_report_cli.py --kind romance --prompt pair_full \
  1990-05-11 17:20 Касимов 1992-01-10 04:30 Москва

# рассылка гороскопа дня (то же, что кнопка в /admin/broadcast):
uv run python scripts/broadcast_cli.py --dry-run     # охват, без отправки
uv run python scripts/broadcast_cli.py               # за сегодня по Москве
uv run python scripts/broadcast_cli.py --date 2026-08-25

# сверить дату с astro-seek и записать новый эталон:
uv run python scripts/seek_check.py 1993-02-01 12:00 Пермь
uv run python scripts/natal_cli.py 1993-02-01 12:00 Пермь --json > tests/golden/1993-02-01_perm.json
```
